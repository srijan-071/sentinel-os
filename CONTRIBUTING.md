# Contributing to SentinelOS

Thanks for contributing. Keep changes focused and explain the problem they solve.

## Before opening a pull request

- Describe the problem and expected behavior.
- Keep security-sensitive changes explicit and reviewable.
- Add or update tests when behavior changes.
- Run the relevant checks locally when practical.
- Do not commit credentials, tokens, or other secrets.

## Pull requests

Use a concise title and include what changed, why it changed, and how it was verified.
