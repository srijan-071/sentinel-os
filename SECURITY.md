# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability.

When reporting a security concern, include:
- a clear description of the issue and affected component;
- steps to reproduce or a minimal proof of concept, when safe to provide;
- the potential impact and relevant environment details;
- any relevant logs or proof-of-concept details that do not expose real credentials.

Do not include passwords, API keys, tokens, personal data, or other secrets in the report.

## Scope

This policy covers security issues in the SentinelOS repository and its maintained code. Third-party dependency issues should be reported to the relevant dependency maintainers when the issue is not introduced or controlled by this project.

## Response

Security reports will be reviewed as soon as practical. Please allow maintainers time to validate, remediate, and coordinate disclosure before publicly discussing an unresolved issue.
