# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability.

When reporting a security concern, include:

- A clear description of the issue and affected component.
- Steps to reproduce or a minimal proof of concept, when safe to provide.
- The potential impact and relevant environment details.

Do not include passwords, API keys, tokens, personal data, or other secrets in the report.

## Safe handling

Until a vulnerability has been reviewed, avoid publicly disclosing exploit details that could put users at risk. Security-sensitive changes should remain focused and include verification steps.
